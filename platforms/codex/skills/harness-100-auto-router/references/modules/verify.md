# verify

요구사항별 성공 기준과 실제 확인 방법을 정한다. 정상 사례뿐 아니라 관련 반례·실패·회귀 사례를 확인한다. 코드 실행이 허용되는 작업에서는 통제된 환경에서 필요한 검사를 실행하고 명령·종료 코드·출력을 기록한다.

프롬프트 전용·읽기 전용·실행 금지 작업에서는 검증 계획과 기존 증거 대조까지만 수행한다. 테스트 정의의 존재, 사용자가 전달한 passed 값, README, 점수 보고서, 정성적 자기 점검은 실행 증거가 아니다. 실행하지 않은 테스트는 PASS로 표시하지 않는다.

PASS·FAIL·미검증을 기준별로 기록하고 실패 기록을 보존한다. 최초 검증 이후 수정·재검증은 전체 작업에서 최대 2회이며 [공통 코어](../CORE.md)의 같은 작업 식별자 ledger를 사용한다.
