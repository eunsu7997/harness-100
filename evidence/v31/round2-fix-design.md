## 규칙 A (G1·G2 안전): 위험 행동은 grant가 그 행동을 명시할 때만 allow

규칙 A는 재검수 판정과 관계없이 적용한다.

- **위험 행동:** push·배포, 삭제, 네트워크, 설치, commit.
- **판정 순서:**
  1. 명령을 정규화한다(아래).
  2. 정규화한 명령으로 위험 행동을 분류한다.
  3. 위험 행동이 있으면, grant 접두가 그 행동을 같은 위치에 명시해야 한다. 예: `실행 git push`는 정규화 결과 `git push …`를 덮는다.
  4. 접두어가 프로그램 이름뿐이면(`실행 git`, `실행 pip`) 위험 행동을 덮지 않는다.
- **정규화:**
  - git 전역 옵션을 걷어 내고 하위 명령을 찾는다. 대상: `-C <경로>`, `-c <키=값>`, `--git-dir[=]`, `--work-tree[=]`, `--namespace[=]`, `--exec-path[=]`, `-P`, `--no-pager`, `--paginate`, `--bare`, `--literal-pathspecs` 등.
  - 정규화 과정에서 걷어 낸 옵션이 하나라도 있는 위험 명령은 allow하지 않는다. 다른 저장소나 설정을 대상으로 할 수 있기 때문이다.
  - `-c alias.*` 또는 `-c core.*`처럼 실행할 동작을 바꾸는 설정이 있으면, 위험 행동 "알 수 없음"으로 보고 allow하지 않는다.
  - `python -m pip …`는 `pip …`로 본다.
  - `pip download`는 네트워크로, `pip install/uninstall`은 설치·삭제로 분류한다.
- **회귀 테스트:**
  - allow되면 안 되는 명령: `승인: 실행 git`에서 `git -C . push origin main`, `git --git-dir=x push`, `git -c alias.x=push x`. `승인: 실행 pip`에서 `pip download x`, `pip install x`, `python -m pip install x`.
  - allow돼야 하는 명령: `승인: 실행 git push`에서 `git push origin main`. 단 `git -C . push`는 걷어 낸 옵션이 있으므로 allow되면 안 된다.

## 규칙 B (grant 줄 엄격화): 해석이 갈리면 엄격하게

규칙 B도 재검수 판정과 관계없이 적용한다.

- **메시지 단위:** 사용자 메시지 전체(앞뒤 ASCII 공백·줄바꿈 제외)가 grant 줄 하나일 때만 grant로 인정한다. 요청 문장과 같은 메시지에 있는 grant 줄은 인정하지 않는다. 인용·코드 블록·붙여 넣은 글 안의 grant 줄도 무시한다.
- **문자 형식:**
  - 머리말은 소문자 `승인:` 또는 `grant:`이고, 콜론 뒤에 ASCII 공백 한 칸이 와야 한다.
  - 대문자(`GRANT:`), 전각 문자(전각 콜론·전각 공백 등 NFKC로 바뀌는 문자), 탭, 서식 문자(U+200B 등)가 메시지 어디에든 있으면 거부한다.
- **구분자:** ` · `, `; `, ` / `만 인정하며, 앞뒤 공백은 ASCII 공백이어야 한다.
- **영향:** "grant 줄 + 요청"을 한 메시지로 보내던 사용 방식은 더 이상 grant가 되지 않는다. 사용자는 grant를 별도 메시지로 먼저 보내야 한다. 사용성 세트에는 같은 메시지 grant 항목이 있으므로 재확인율이 오를 것으로 예상하며, 측정한 그대로 보고한다.
- **문서:** `docs/GRANT-SPEC.md`의 형식 절을 이 규칙으로 바꾼다. 이 명세 변경은 사용자 결정이며, 사용성 세트·세트 D 작성 뒤의 변경이라는 점을 함께 적는다.
- **회귀 테스트:**
  - 거부: `GRANT: edit src/**`, `승인:\t수정 src/**`, `승인: 수정\tsrc/**`, `승인: 수정 src/**　·　실행 pytest`(전각 공백), `승인： 수정 src/**`
  - 거부: `승인: 수정 src/**\n이제 고쳐줘`(같은 메시지에 요청 포함), 코드 블록·`>`·따옴표 안의 grant 줄
  - 인정: `승인: 수정 src/** · 실행 pytest`(단독 메시지), 같은 줄의 앞뒤 공백

## 1. plan 모드 쓰기 (G2 위반 원인)

- plan 모드를 쓰기 기준 "확인 창이 없는 모드"로 분류한다. grant 밖 Write·Edit·MultiEdit·NotebookEdit와 쓰기 Bash는 deny한다. Claude Code의 계획 파일(`~/.claude/plans`)도 예외 없이 deny한다(사용자 결정 (가)).
- 모드와 관계없이, 대상 경로가 세션 작업 폴더(cwd) 밖인 쓰기 도구 호출은 deny한다. grant는 프로젝트 기준 상대 경로만 허용하므로 이 규칙은 grant와 충돌하지 않는다.
- 회귀 테스트: plan 모드에서 프로젝트 안 Write는 grant가 없으면 deny, 있으면 allow. `~/.claude/plans/x.md` Write는 모든 모드에서 deny.
